## 目标

回答一个问题：**Unity 6000.6（Unity 6.3 LTS）下，中文字体的动态 SDF 图集到底能不能用？**

产出一个**书面结论**（可用 / 不可用 / 有替代方案），并留下可复现的验证场景。这个结论会决定 P2/P3/P4 三个系统怎么做——所以**先出结论，再谈好不好看**。

> 这条对应 `docs/engine-reference/unity/VERSION.md` 人工核对清单第 4 项。该版本超出多数模型训练数据，**不许凭记忆断言**，必须实测。

---

## 范围

- [ ] 下载并入库**思源宋体 Source Han Serif**（SIL OFL 1.1），保留 LICENSE 文件
- [ ] 生成**子集**：50 个目标字（见 `Data/char-table.json` 的 `char` 字段）+ UI 常用字（数字、标点、中英菜单约 100 字）
- [ ] 用 TextMeshPro 配**动态 SDF 图集**（Atlas 2048×2048，Dynamic 模式），渲染全部 50 字
- [ ] 记录：图集页数、Atlas 显存占用、最小字号下的清晰度、是否有缺字/糊边
- [ ] 最小竖排可行性验证：垂直排 5 个字，观察标点位置与行距
- [ ] 尝试**备选路线**：UI Toolkit 的 Text 组件在 6000.6 下能否渲染同样 50 字
- [ ] 把结论写进 `docs/tech-validation.md`（新建），含截图路径

## 不做什么（必填）

- ❌ 不做墨晕/飞白 shader（那是 P5）
- ❌ 不做完整竖排排版组件（只验"竖着排能不能排"，不要求标点规则完美）
- ❌ 不改 `design/gdd/` 下任何文档
- ❌ 不改 `Data/*.json`（字表已定稿）
- ❌ 不做 UI 布局、不做 HUD
- ❌ **不许打包任何系统字体**（苹方、微软雅黑等一律禁止，见 P4 R1）

## 步骤建议

1. 从 Adobe/Google Fonts 取 Source Han Serif（OFL），放 `Client/Assets/Fonts/`，**LICENSE.txt 一并入库**
2. 用 Font Asset Creator 或 `fonttools` 生成子集（避免整包 20,000 字）
3. 建 SDF Font Asset：Atlas 2048²、Dynamic、Padding 5、采样 90
4. 一个测试场景，用 TMP 把 50 个字一次性铺满屏幕（各种字号：16 / 32 / 120）
5. 记录图集页数与显存（Memory Profiler 或 Frame Debugger）
6. 同样内容用 UI Toolkit 的 Text 再试一遍
7. 截图 → 写结论

**验收标准引用**

- [ ] 通过 `design/gdd/cjk-typography.md` **A3**（50 字全渲染无缺字、无糊）
- [ ] 通过 `design/gdd/cjk-typography.md` **A4**（图集页数 ≤4）

**可执行验证**

```bash
# 1. 仓库内字体授权检查：只应出现 OFL 系字体
ls -R Client/Assets/Fonts/ | grep -iE "\.(ttf|otf)$"
grep -ril "SIL OPEN FONT LICENSE" Client/Assets/Fonts/ || echo "FAIL: 缺少 OFL LICENSE"

# 2. 构建产物内不得出现系统字体
#    （先做一次 Windows 构建，再检查产物）
find Client/Build -iname "*.ttf" -o -iname "*.otf" 2>/dev/null | grep -viE "sourcehan|notoserif" && echo "FAIL: 发现未授权字体" || echo "PASS: 无系统字体"

# 3. 结论文件必须存在且非空
test -s docs/tech-validation.md && echo "PASS: 结论已写" || echo "FAIL: 缺结论文档"
```

预期输出：

```
PASS: 无系统字体
PASS: 结论已写
```
