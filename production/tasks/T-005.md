## 目标

把 F2/F3 的架构地基从 T-001 的"能编译的最小桩"推进到**可承载后续玩法系统**的骨架：

- `FarmState` 落全 schema v1（田块 / 手牌 / 村民 / 字谱 / 季相），支持**深克隆**与**规范化 JSON 往返**；
- `ICommand` 的两阶段契约（Validate 无副作用 / Apply 原子执行）有唯一的 `Execute` 通道；
- 状态哈希与 canonical JSON 就位，为 T6 的 `ReplayHash` 与 F4 的存档提供唯一输入。

做完之后：任何后续系统（C1–C7、G1–G4）都可以只写命令、经 `GameSession.Execute` 改状态；M4 可以在不启动 Godot 的情况下深拷贝状态、重置实验、比较 hash。

### 结论

**通过。** F3-A1 / A3 / A4 均可执行验证；`dotnet test` 46/46 通过（原 16 条 + 新增 30 条），Sim 不引用 Godot、无静态可变字段、无浮点字段；View 构建与 headless 启动探针通过。

T-001 留下的 `FarmState` 是最小桩（只有版本、RNG、计数器与铜钱/祟气）。本次把 F3 schema v1 补齐并建立了唯一的 `Execute` 通道，后续玩法任务不再需要改状态层结构，只需新增命令类型。

### 关键实现说明

| 点 | 实现 |
| --- | --- |
| 唯一状态实例 | `GameSession` 构造时持有 `FarmState` 与 `DeterministicRng`；`State` 只读暴露 |
| 两阶段 | `Validate` 前先 `Clone` 快照；拒绝则恢复快照并返回 `StepResult.Rejected`（违约写入也不会留下），通过则进入原子 `Apply` |
| Step 原子性 | `Apply` 抛异常 → `CopyFrom(snapshot)` 原地回滚；`assertOnApplyFailure` 默认在 Debug 构建回滚后重抛、Release 回滚并返回 `StepResult.RolledBack`，异常经 `Failure` 交给调用方记录 |
| RNG 书签 | `Execute` 从 `FarmState.RngState` 恢复，成功后写回；被拒绝的 Validate 连随机数消耗也回退 |
| canonical JSON | 键 Ordinal 字典序、枚举字符串名（拒绝数字枚举）、字谱按 `(a,b)` 排序、手牌/牌堆保持顺序、无浮点；`CharId` 的 null 单独写出，缺席 ≠ 空串 |
| 状态 hash | canonical JSON 的 UTF-8 字节做 FNV-1a 64（`FarmStateHash.Compute`） |

### 遗留

- **schema 版本仍为 1**：T-001 的最小 `FarmState` 从未落盘（F4 存档尚未实现），不存在需要迁移的 v1 存档；首个存档格式定版归 F4。
- **事件总线未实现（F2 R7）**：`CommandRejected` / `CharComposed` 等事件要等玩法回路任务统一接入；当前 `StepResult.Rejection` 已携带拒绝原因，但 F2-A5 的"产生 `CommandRejected` 事件"尚未满足。**F2-A5 不能算通过。**
- **`ReplayHash` 未实现（F2 R6）**：本次只提供单状态的 canonical hash；"初始快照 + 种子 + 命令日志"的重放契约归 T6。
- **F4 存档外壳未实现**：文件读写、原子写入、`.bak`、`charTableVersion` / `gameVersion`、迁移链均未做；本任务的序列化只负责状态结构本身。F3-A6 / F4 的版本校验目前只覆盖了"更高版本拒绝"，更低的版本号一律提示需要迁移链。
- **字段顺序表述待 F4 对齐**：F2 §4.2 / F3 §4.1 要求 canonicalJson 键按字典序；F4 R1 写的是"按 F3 的 schema 声明顺序"。本任务按 F2/F3 的字典序实现 hash 输入，并已在 `systems-index.md` §7 登记 **Q11**。F4 落文件格式时需确认：存档文件可以用 schema 顺序，但 hash 必须对同一 canonical 形式计算，否则两套顺序会出现两个 hash。
- **`SeasonState` 字段是本次补的最小集**：F3 schema 只写了"季相与夜次"，未列字段。本次按 C6 R3/R7（`pendingNight`）与 G4 季末展示（祟夜次数）落为 `NightsResolved` / `PendingNight`；C6/C7/G4 后续若要更多夜次字段，按各自 GDD 追加，不改变现有字段含义。
- **字谱部件对规范化归 G1/C3**：`CodexState` 以无序部件对为键，但本次不实现"保存前把 `(glyphIdA, glyphIdB)` 排序"的写入规则（那是 G1/C3 的契约）；canonical 序列化只保证集合迭代顺序稳定。
- **F3-A2 / A5–A10 不在 T5 范围**：整季运行、双 actor、存档边界、体积与村民系数都要等 C1–C7 / G4 的命令落地；本任务只对 A1/A3/A4 负责，F3-A5 待第一条带 `EntityId` 的命令。
- **新局初始化未做**：`new FarmState()` 是"全 Locked + 0 铜钱"的空白状态；90 铜钱 / 6 块已开垦田 / 地力 100 / 初始牌堆由 T14 / C2 / G4 负责。
- **`dotnet test` 是本机门禁**：仓库暂无 CI（与 T-001 相同），改动需在合入前本地复跑上面的命令。
