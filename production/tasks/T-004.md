## 目标

在 **Godot 4.7.2（.NET）** 下验证一条 Steam 链路：初始化、回调泵、一个成就上报。产出一个明确的技术选型结论：

- **GodotSteam**（GDExtension）能否与 Godot 4.7.2 **.NET** 工程配合（C# 调用）；
- 或 **Steamworks.NET** 能否在 Godot 的 .NET 运行时里加载原生 `steam_api`；
- 以及**导出后的构建**（不是编辑器里）是否仍能上报。

上架死线要求第一个月跑通，不接受“编辑器里能跑、导出后不行”。

---

## 范围

- [ ] 记录本机 Steam 客户端版本与 AppID 来源（**AppID / 凭据不入库**，用环境变量或本机配置）
- [ ] 分别评估 GodotSteam 与 Steamworks.NET 对 Godot 4.7.2 .NET 的兼容性（版本、原生库、C# 绑定）

## 步骤建议

1. 先查 GodotSteam 与 Steamworks.NET 的最新版本、对 Godot 4.7 / .NET 8 的支持说明；记录链接与版本
2. 用最小工程分别试装（先不改主工程，避免污染）
3. 初始化 Steam（`SteamAPI.Init` 或 GodotSteam 的初始化），确认 `SteamAPI.RestartAppIfNecessary`
4. 加一个成就上报，确认回调 / 异步结果
5. 导出 Windows x64（或 macOS），把原生库放对位置，重跑
6. 用 Steam 客户端 / 日志确认成就真的点亮
7. 写结论、版本锁定、原生库放置说明
