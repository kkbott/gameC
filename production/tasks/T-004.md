## 目标

在 **Godot 4.7.2（.NET）** 下验证一条 Steam 链路：初始化、回调泵、一个成就上报。产出一个明确的技术选型结论：

- **GodotSteam**（GDExtension）能否与 Godot 4.7.2 **.NET** 工程配合（C# 调用）；
- 或 **Steamworks.NET** 能否在 Godot 的 .NET 运行时里加载原生 `steam_api`；
- 以及**导出后的构建**（不是编辑器里）是否仍能上报。

上架死线要求第一个月跑通，不接受“编辑器里能跑、导出后不行”。

## 执行记录（承接人填）

### 结论

**有条件通过（编辑器内）**：GodotSteam 4.24 只提供整包编辑器/模板，不能用于现有 .NET 工程；Steamworks.NET 托管程序集在 Godot 4.7.2 .NET 8 下加载失败（`COR_E_FILELOAD 0x80131621`，多个版本与自编译版本均复现）。改走 **Valve `steam_api` flat C API 的 P/Invoke**，在编辑器内完成初始化 → 成就 `false → true`。**导出构建与产品 AppID 未完成。**

### 数据

| 项 | 实测值 |
| --- | --- |
| 选型 | 直接 P/Invoke `steam_api` flat API（Steamworks SDK 1.65） |
| 插件版本 | 无托管插件；原生库来自 Steamworks.NET Standalone `2025.165.0` 内的 SDK 1.65 |
| Godot / .NET 版本 | Godot 4.7.2 stable mono / .NET 8.0.34（SDK 8.0.428） |
| 编辑器内初始化 | 成功（`SteamAPI_InitSafe()=true`，`IsSteamRunning()=true`） |
| 导出构建初始化 | **未验证**（缺 4.7.2 mono 导出模板） |
| 成就上报 | 编辑器内成功：`set_ok=True store_ok=True achieved_before=False achieved_after=True` |
| 原生库放置 | 编辑器：`Client/native/macos/libsteam_api.dylib`；导出：与可执行文件同级 |

### 原生库与导出规则

- `Client/native/.gdignore` 阻止 Godot 把原生库当资源导入。
- 编辑器：`NativeLibrary.SetDllImportResolver` 指向 `res://native/macos/libsteam_api.dylib`。
- 导出：`libsteam_api.dylib` 必须与 `TianziGe` 可执行文件同级（`Contents/MacOS/`）；
  不能放在 PCK 内（`dlopen` 无法打开包内文件）。
- Windows：`steam_api64.dll` 与 `TianziGe.exe` 同级；未实测。
- flat API 访问器带版本后缀（`SteamUserStats_v013` / `SteamUtils_v011` / `SteamUser_v023`），
  升级原生库时必须 `nm -gU` 核对符号。
