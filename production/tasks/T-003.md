## 目标

验证**一条完整的数据链路**能跑通：

```
Client/Data/*.json（源）
  → Godot FileAccess 从 res://Data 读取文本
  → TianziGe.Sim 用 System.Text.Json 解析成只读字典
  → 导出 Windows / macOS 产物后，读到的条目数仍与源一致
```

这个任务的结论决定 F1 / C3 / C4 / C2 后续怎么读数据；**不实现玩法规则**，只证明数据进得了包、Sim 解析得了、View 拿得到。

> 原 Unity 选型下的 T-003 是 "Addressables 2.x 验证"。Godot 重新立项后改为**导出包内 JSON 是否可达**——这是 Godot 下同等的风险点。见 `docs/architecture/002-data-source-json.md`。

---

## 范围

- [ ] 在 `Sim/` 加一个最小 `CharTableLoader`：输入 `string json`，输出只读条目集合；不做完整 schema 校验（T-007）
- [ ] 在 View 侧加一个最小加载入口：`FileAccess.GetFileAsString("res://Data/char-table.json")` → 交给 Sim
- [ ] 验证开发运行（`godot --path Client`）下能读到 50 条
- [ ] 验证 `godot --headless --path Client -- --data-probe` 输出 `chars=50, components=26`
- [ ] 做一次导出（Windows x64 优先；macOS 次之），确认 JSON 在导出包内（`res://Data/`）且能读到
- [ ] 把结论写进 `docs/tech-validation.md` 的 T-003 段（含导出配置：过滤 / 包含 / 打包方式）
- [ ] 记录“哪些文件进包 / 哪些不进包”的规则，供后续美术资源复用

## 步骤建议

1. 在 Scan 前先确认 `project.godot` 的导出资源过滤设置（Godot 4 的 `export_presets.cfg` / 资源过滤；以 4.7 文档为准）
2. 写 `CharTableLoader`（Sim）：只解析 `chars` 与 `components` 两个数组，返回 `IReadOnlyList`；字段缺失抛明确异常
3. 写 View 的 `DataProbe`（或复用 `Bootstrap` 的 `--data-probe` 分支）：读文件、调用 Sim、打印条目数
4. 用 `godot --headless --path Client -- --data-probe` 验证开发路径
5. 配置导出模板（首次需要下载 Godot 4.7.2 export templates，约 1.2 GB；记录实际版本）
6. 导出 Windows x64（若当前 macOS 不能交叉导出，记录限制并改用 macOS 验证；不要伪造 Windows 结果）
7. 解包 / 检查导出目录，确认导出包内 `res://Data/*.json` 存在且条目数正确
8. 写结论与导出配置
