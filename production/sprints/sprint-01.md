# Sprint 01 · 可行性原型（第 1 个月）

> **状态**: 执行中（T1 已完成，2026-11-17）
> **周期**: 4 周（第 1 个月）
> **目标**: 回答**唯一一个问题**——「合字本身体验好不好？」
> **依据**: `design/gdd/systems-index.md` 设计顺序 1–6 + 技术验证清单

---

## 1. 冲刺目标（Definition of Success）

冲刺结束时，必须能用一句话回答：

> **拖两个偏旁进田、合成一个字、看它生效——这件事本身好玩吗？**

判断方式：**自己关掉调试信息连续玩 20 分钟不想停**，且能说出至少 3 种不同的解法偏好。做不到，就停在这里，不投美术。

**明确不是目标**：好看的画面、完整四季、字灵、村民、Steam 上架。

---

## 2. 范围

| ✅ 在范围内 | ❌ 不在范围内 |
| --- | --- |
| Godot 工程 + Sim/View 分层骨架 | 完整美术资源、动画 |
| 三项技术验证（CJK / 数据打包 / Steam） | Steam 商店页、预告片 |
| 50 字表导入 + 构建期校验脚本 | 300 字内容生产 |
| 3 块田 + 手牌 + 合字校验 + 字效 | 祟夜、祟气、村民、字灵 |
| 1 回合循环（可重复） | 四季、季末结算、存档 |
| M4 控制台工具雏形（能跑命令序列） | M4 的平衡门槛校准（需 60 字表） |

**刻意砍掉的**：祟夜与祟气不在本月。**先验"写字爽不爽"，再验"守不守得住"**——如果写字都不好玩，守夜做得再好也没用。

## 8. 冲刺结束后的分叉

| 结论 | 下一步 |
| --- | --- |
| **好玩** | Sprint 02 = 加入祟气 + 祟夜 + 存档，跑通完整一季 |
| **不好玩，但问题可定位** | 修 1–2 个核心问题（通常是手感或失败惩罚），再跑一次 20 分钟测试 |
| **不好玩，且说不清为什么** | **停下来回到概念阶段**。这是最便宜的时刻，投美术之后就不是了 |
