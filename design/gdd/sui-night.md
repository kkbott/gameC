## 概述

祟夜是**整个游戏唯一的高潮**：祟顺着水口进来，你白天写下的每一个字就是今晚的防线。

它的设计关键是**玩家在祟夜当晚不做任何操作**——字格锁定，只能用已写好的字阵去扛。这一条把"经营"和"防守"焊成了同一件事：**你白天的每一个布局决策，都是今晚的一票**。它同时满足了"有真实外部压力"和"单人可控复杂度"，是本作最重要的结构决定。

---

## 玩家幻想

> **「今晚这片地，是我白天写的。」**

- 祟夜开始时玩家的第一反应应该是**算账**："我写了两个林、一个明，够不够。"
- 守住的时候是**释然**，不是爽快——"扛过去了"。
- 漏祟的时候是**肉疼**，因为毁掉的是他亲手写的那块田，不是抽象的血量。
- 字灵在祟夜前后说话最多——它是这晚唯一的同伴，也是这晚唯一会嘲笑你的东西。

## 详细设计

### 核心规则

**R1 · 触发与流程**

```
触发：C6 在回合结算第 3 步置 pendingNight
执行：同一回合结算的第 5 步（F2 R5 固定顺序）
属性：原子 Step —— 无中间态、不可中断、不存档
字格：锁定。C3 的任何合字命令返回 locked
```

**R2 · 三波结构**

祟夜分 **3 波**进入，波次有先后（给 `ward_wave` 等模板语义落点）：

```
波 1: e1 = E × 0.30
波 2: e2 = E × 0.35
波 3: e3 = E × 0.35
```

**R3 · 敌力 E**

```
E = BASE[seasonIndex] × (1 + 0.15 × openedPlots) × (1 + 0.10 × expansionsThisSeason)

BASE        = { 春: 2.0, 夏: 2.6, 秋: 3.2, 冬: 4.0 }      // 春=季序0
openedPlots = 已开垦田块数（6..12）
expansionsThisSeason = 本季开垦次数（0..6）
```

> **这条公式就是"外部入侵压力促使玩家发展"的数学表达**：你开垦得越多、今年扩得越凶，今晚的祟就越重。发展本身自带抵押。

**R4 · 防力 D**

```
D_base = Σ battleWill_eff(场上字)          // 逐字取 F1 §4.1
D      = D_base × (1 + 0.1 × (villagers − 5)) × seasonCoef

seasonCoef = { 春: 0.90, 夏: 1.00, 秋: 1.15, 冬: 1.30 }
villagers  = FarmState.VillageState.Count（MVP 初值 5，只减不增，下限 2）
```

**R5 · 隐身祟（裁决悬置项 Q6）**

**决定：做，但极简。** 祟夜中 **25% 的敌力是"隐"的**：

```
hiddenShare = 0.25
hasReveal   = 场上存在 template == reveal_stealth 的字
effectiveD(wave) = hasReveal ? D_current : D_current × (1 − hiddenShare)
```

不做"隐身单位实体"、不做闪避判定、不做可见性系统——**只有一个乘法**。这样 `reveal_stealth` 模板有了确定的行为，而 C7 不需要新增任何子系统。

**R6 · 逐波判定（防力会随毁田下降，形成递进）**

```
for wave in 1..3:
    D_w = effectiveD(wave) + waveBonus(wave)
    if D_w >= e_wave:
        守住该波
    else:
        deficit = e_wave − D_w
        destroyCount = ceil(deficit / 3)                 // 每 3 点缺口毁一块田
        destroyed = 按战意降序选 destroyCount 块 Char 田（同分按 PlotIndex 升序）
        每毁一块：Status = Sui，Soil −= 50
        // 被毁的田若原本提供战意，会自然降低后续波次的 D_current
```

**波次加成（来自模板）**

| 模板 | 作用波次 | 效果 |
| --- | --- | --- |
| `ward_wave` | **仅第 1 波** | 该波 `waveBonus += 2`（每块这样的田各 +2） |
| `will_boost` | 全部 | 已计入 `battleWill_eff`（+2），不重复 |
| `reveal_stealth` | 全部 | 见 R5 |

**R7 · 结果结算**

| 结果 | 效果 |
| --- | --- |
| 三波全守住 | 铜钱奖励 `nightReward = 20 + 10 × seasonIndex`（C5 执行）；**祟字残片**掉落（稀有偏旁进入 C2 牌池，下季生效）；村民信心 +1（G2 落地前为记日志） |
| 有波次漏掉 | 毁田（R6）；**村民 −1**（下限 2）；无奖励 |
| 三波全漏 | 同上，且额外：本季剩余回合的 `NATURAL_DRIFT` +1（这片地被记住了） |

**R8 · 祟夜结束后**

```
QiOfSui = 0
pendingNight = false
被毁田块：Soil −50，状态 Sui（需玩家用 C3 的清除路径处理）
```

### 状态和转换

```
Idle --[pendingNight]--> Wave1 --[守/漏]--> Wave2 --[守/漏]--> Wave3 --[守/漏]--> Resolve --> Idle
```

每一波是同一 Step 内的子阶段，**不产生可中断边界**。

### 与其他系统的交互

| 系统 | 方向 | 接口 | 所有权 |
| --- | --- | --- | --- |
| C6 祟气 | 上游 | 接收 `pendingNight` 与 `QiOfSui`；结算后通知归零 | C6 拥有触发 |
| F1 字表 | 上游 | 读 `battleWill_eff`、`template` | F1 拥有数值 |
| C4 字效 | 上游 | `ward_wave` / `reveal_stealth` 的行为 | C4 声明模板，C7 实现其防守语义 |

| G2 村民 | 下游 | 村民 −1（MVP 直接改 `Count`，下限 2） | G2 拥有规则，MVP 由 C7 直接执行 |

| P5 / P6 / P3 | 下游 | 抛 `night_started` / `wave_resolved` / `night_ended` | — |

## 公式

### 4.1 敌力与防力

```
E = BASE[s] × (1 + 0.15×opened) × (1 + 0.10×expansions)
D = (Σ battleWill_eff) × (1 + 0.1×(villagers−5)) × seasonCoef[s]
```

### 4.2 逐波

```
e = [0.30E, 0.35E, 0.35E]
D_eff = hasReveal ? D_cur : 0.75 × D_cur
deficit_w = max(0, e_w − D_eff − waveBonus_w)
destroyCount_w = ceil(deficit_w / 3)
```

### 4.3 参考数值（春季、12 田、无扩张、村民 5）

```
E   = 2.0 × (1 + 0.15×12) × 1.0 = 2.0 × 2.8 = 5.6
        e = [1.68, 1.96, 1.96]

假设玩家写了 6 个 tier1 防御字（战意各 1）= D_base 6
D   = 6 × 1.0 × 0.90 = 5.4
D_eff（无明）= 4.05

波1: 4.05 ≥ 1.68 守
波2: 4.05 ≥ 1.96 守
波3: 4.05 ≥ 1.96 守            → 全守，拿奖励

若玩家只写了 2 个 tier1 防御字（D_base 2）：
D = 1.8, D_eff = 1.35
波1: 1.35 < 1.68 → 缺口 0.33 → 毁 1 块田
波2: D 降到约 0.9×1.8=... → 继续漏
```

> 这组数字说明：**春季 6–8 个战意点是安全线**。它给了 60 字表一个明确的"守夜预算"，也是字表设计（R7 类别覆盖）的依据。

## 边缘情况

| # | 情况 | 处理 |
| --- | --- | --- |
| E1 | 场上没有任何字 | `D = 0`，三波全漏，毁田数按缺口算但**最多毁到只剩 1 块可写田**（防清空） |
| E2 | 场上全是祟字 | 同上（祟字不提供战意），且 C6 下回合 ΔQ 爆炸 |
| E3 | 守住的波次后 D 不变 | 是的——本作没有"塔掉血"，防线只通过**毁田**下降 |
| E4 | 同一波要毁多块田，但 `Char` 田不足 | 毁光为止，剩余缺口不累积到下一波 |
| E5 | 村民降至下限 2 | 不再下降；公式系数变为 0.7 |
| E6 | `ward_wave` 在第 2、3 波 | **不生效**，只在第 1 波（R6） |
| E7 | 祟夜当回合同时是季末 | 祟夜先（第 5 步），季末后（第 7 步）；季末洗田会清掉刚被毁成 `Sui` 的田吗？**不会**——`Sui` 不参与洗田，必须玩家自己清 |
| E8 | 玩家在祟夜前把田全写成 `Sui` | 允许但极蠢（D=0 且 ΔQ 爆炸），不需要额外规则 |
| E9 | 读档回到祟夜前 | 祟夜是原子 Step，读档后重放同一命令序列必然得到同一结果（F2 A2） |

## 调整旋钮

| 旋钮 | 初值 | 安全范围 | 太高会怎样 | 太低会怎样 |
| --- | --- | --- | --- | --- |
| `BASE[季]` | 2.0 / 2.6 / 3.2 / 4.0 | ×0.7–×1.5 | 中后期必漏，玩家放弃防守 | 祟夜无威胁，变成例行公事 |
| 开垦系数 | 0.15 | 0.08–0.25 | 扩张被重罚，玩家不敢开荒 | 扩张无代价，最优解是无限开垦 |
| 扩张冲动系数 | 0.10 | 0.05–0.20 | 本季扩张即找死 | 扩张时机无所谓 |
| `seasonCoef` 跨度 | 0.90–1.30 | 0.8–1.5 | 冬季必崩 | 季节无难度差 |
| 每点缺口毁田数 | 1 / 3 | 1/2–1/6 | 一漏就毁一片，挫败 | 漏了不痛，压力消失 |
| 隐身份额 | 0.25 | 0.15–0.35 | 不写 `明` 就必漏，强制指定解 | `明` 无价值 |
| 波次分配 | 30/35/35 | — | 前重后轻 = 开局就崩 | 前轻后重 = 无悬念 |
| 守住奖励 | 20 + 10×季序 | 10–40 | 防守成主要收入 | 守夜不值得 |

**旋钮联动**：`BASE` 与"每点缺口毁田数"是一对——提高 `BASE` 必须同时放宽毁田数，否则容错归零。

## 视觉/音频需求

- **三波必须有明确的节奏**：波与波之间留 1–2 秒的静默，让玩家听见自己的心跳。
- 毁田瞬间：该田的字**被撕开**（不是淡出），焦痕从字的位置向外扩散。
- 全守住：天亮的过程要走完整，不能跳过——这是玩家应得的。
- 字灵在祟夜中的台词密度最高，它是唯一的同伴。
- 细则归 P5 / P6 / P3。

## UI需求

- 祟夜开始前，**必须给一屏结算预览**：当前 D、本夜 E 的估算区间、玩家自己判断够不够。
  > 这是"算账"幻想的落地。不给这屏，玩家只能盲扛，祟夜会变成掷骰子。
- 逐波推进要有可读的结算顺序（波次、守/漏、毁田）。
- 字格锁定期间，手牌区应明确显示"今晚写不了"。

## 验收标准

- [ ] **A1** `E` 三个因子计算正确；春季 12 田无扩张时 `E = 5.6`（用例）
