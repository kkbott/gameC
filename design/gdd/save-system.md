# F4 · 存档（Save System）

> **状态**: 设计中 · v0.1
> **作者**: 创意总监 + agent
> **最后更新**: 2026-11-17
> **实现支柱**: P4 一季不回头（存档是"不可回退"的技术保证：只存当前点，不存历史）
> **系统层级**: 基础层 / MVP / 设计顺序第 11
> **上游**: [F3 状态层](farm-state.md) v0.1、[F2 步进](deterministic-step.md) v0.1

---

## 概述

F4 把 `FarmState` 序列化成一坨 JSON，再原样读回来。听起来简单，但它承载了两件非常重要的东西：

1. **不可回退的执行者**：只有一个存档点，没有"上一回合"，没有回滚历史。P4 支柱靠它成立。
2. **可复现的保证**：存档 + 命令日志 + 种子 = 完整的一局。这是 M4 回归和用户报 bug 的基础。

它的设计原则只有一条：**宁可拒绝加载，也不要加载出半个世界。**

---

## 玩家幻想

玩家对存档的唯一期待是**"关掉再来，地还在"**。它必须完全无感：

- 不出现存档图标、不出现"正在保存"遮挡画面。
- 卡死/崩溃/断电后重开，损失不超过一个回合。
- 绝不出现"存档损坏"把人一整晚的心血清零。

## 详细设计

### 核心规则

**R1 · 格式**

- 单一 JSON 文件（System.Text.Json），UTF-8，无 BOM。
- **字段顺序固定**（按 F3 的 schema 声明顺序），便于人工 diff 与 hash 稳定。
- 数字一律整数或定点字符串；**禁止浮点**（与 F2 §4.1 一致）。
- 枚举以**字符串名**写出（`"Char"`、`"produce"`），不用整数——可读性与向前兼容更重要。

**R2 · 存什么 / 不存什么**

| 存 | 不存 |
| --- | --- |
| 整个 `FarmState`（含 `RngState`、`DrawPile`、`Codex`、`Plots`、`Village`、`QiOfSui`） | `CharDef` 字表内容（只存 `charTableVersion` 做校验） |
| `SaveVersion`、`charTableVersion`、`gameVersion` | 相机、音量、键位（属 M1 设置，另一文件） |
| `ReplayHash`（季末快照，用于完整性校验） | 命令日志（发行版默认不存，见 F2 Q1） |
| 存档时间戳、季/回合序号（供 UI 展示） | 任何表现层状态、任何 Unity 对象引用 |

**R3 · 原子写入（防中断损坏）**

```
1. 写入 <slot>.tmp
2. flush + fsync
3. 若 <slot>.json 已存在 → 重命名为 <slot>.json.bak
4. <slot>.tmp 重命名为 <slot>.json
```

- 任一步失败 → 保留 `.bak` 与原档，报错给玩家，**不删除任何东西**。
- 崩溃后若存在 `.tmp` → 视为**未完成的写入**，直接删除，使用 `.json` 或 `.bak`。

**R4 · 槽位设计**

| 槽 | 数量 | 写入时机 |
| --- | --- | --- |
| 自动存档 | 1 | **每回合结算后**（不是每步，避免频繁 IO） |
| 手动存档 | 3 | 玩家主动 |
| 备份 | 1 | 每次覆盖 `auto` 前自动留一份 |

- 本作**没有"回档到上一回合"的功能**——`.bak` 只用于**损坏恢复**，不作为玩法手段。
- 这意味着 `.bak` 不应在 UI 暴露"读取备份"按钮，只在检测到主档损坏时静默尝试。

**R5 · 加载流程**

```
1. 读取 .json → 解析失败？ → 尝试 .bak
2. 校验 SaveVersion：
     高于程序版本 → 拒绝，提示"此存档来自更新的版本"
     低于程序版本 → 进入迁移链
3. 校验 charTableVersion：
     不一致 → 按 F3 E3 处理（失效 CharId 转 Sui 并记警告），不拒绝
4. 校验 ReplayHash（若存在）：
     不一致 → 警告日志，但仍加载（hash 不一致可能是合法的数值调整）
5. 成功 → 构建 FarmState
```

**R6 · 迁移链**

```
MIGRATIONS = {
  1 → 2: ...,
  2 → 3: ...,
}
逐级执行，每步都有单测
```

- 迁移必须是**纯函数**：`Migrate(fromVersion, json) -> json`。
- 不允许"跳级迁移"——防止迁移逻辑组合爆炸。
- 迁移失败 → 拒绝加载，保留原档，提示用户。

**R7 · 云存档兼容（为 M2 预留）**

- 存档是**单文件**，无外部依赖 → Steam Cloud 可直接同步。
- 不做"多设备冲突合并"：以修改时间戳较新者为准，并在 UI 提示"已使用较新的云存档"。
- `Auto-Cloud` 路径用 Steam 的 API，不用自建。

### 状态和转换

```
NoSave --[首局开始]--> AutoExists
AutoExists --[回合结算]--> AutoExists (覆盖，先备份)
AutoExists --[损坏]--> TryBackup --[成功]--> AutoExists
TryBackup --[失败]--> LoadFailed (拒绝，保留文件)
```

### 与其他系统的交互

| 系统 | 方向 | 接口 | 所有权 |
| --- | --- | --- | --- |
| F3 状态层 | 上游 | `Serialize/Deserialize(FarmState)` | F3 拥有结构 |
| F2 步进 | 上游 | `ReplayHash` 季末快照 | F2 拥有 hash |
| G4 季相 | 下游 | 提供存档触发点（回合结算后） | G4 决定何时存 |
| M1 设置 | 平行 | 独立的 settings 文件，不混在一个档里 | M1 拥有 |
| M2 云存档 | 下游 | 单文件同步 | M2 拥有 |

## 公式

```
存档体积 ≈ base(FarmState) + codex(≤500 对) + drawPile(≤8) + plots(12)
目标：< 120 KB
hash = F2 §4.2 FNV1a64(canonicalJson)
```

## 边缘情况

| # | 情况 | 处理 |
| --- | --- | --- |
| E1 | 写入过程中断电 | `.tmp` 残留 → 启动时删除；主档与 `.bak` 至少有一个可用 |
| E2 | `.json` 与 `.bak` 都损坏 | 拒绝加载，**不覆盖任何文件**，提示"存档损坏，请联系支持并附上文件" |
| E3 | 存档版本高于程序 | 拒绝，提示更新游戏。**不尝试"尽力解析"** |
| E4 | 迁移链中途抛异常 | 中止，原档不动，提示。**不做部分迁移** |
| E5 | 磁盘满 / 无写权限 | 报错并**保留旧档**；自动存档失败时给一次显著提示（否则玩家以为存上了） |
| E6 | 玩家在祟夜中强制退出 | 不可能存到祟夜中间态（原子 Step）。自动存档点是回合结算后 |
| E7 | 存档来自修改过的客户端（作弊） | 不做防护（单机游戏，作弊不伤害他人）。仅记录 hash 不一致 |
| E8 | 两个槽位同时被写（并发） | 单进程游戏，理论上不可能；实现上仍对文件加排他写锁 |

## 调整旋钮

| 旋钮 | 初值 | 说明 |
| --- | --- | --- |
| 自动存档频率 | 每回合结算后 | 调高更安全，IO 更频繁；调到"每步"会卡帧 |
| 手动槽数 | 3 | 1–5 |
| 是否保留 `.bak` | 是 | 关闭会显著提高损坏不可恢复风险 |
| 命令日志入档 | 否 | 开启便于 bug 再现，体积翻数倍（F2 Q1） |

## 视觉/音频需求

无。**刻意不做**存档图标闪烁——它只会制造焦虑。

## UI需求

- 只在**失败时**提示（损坏/磁盘满/版本不符），成功时静默。
- 加载失败必须给出**具体原因**与"存档文件位置"，不能只说"加载失败"。
- 若使用了 `.bak` 恢复，应告知玩家"已从备份恢复"，让他知道发生了什么。

## 验收标准

- [ ] **A1** `Deserialize(Serialize(s))` 后 `hash` 完全一致（F3 A3）
- [ ] **A2** 输出 JSON 中无浮点数（正则检查）
- [ ] **A3** 字段顺序稳定：同一状态两次序列化输出字节一致
- [ ] **A4** 原子写入：模拟在写 `.tmp` 后中止，重启后能用主档或 `.bak`
- [ ] **A5** 主档损坏时自动回退 `.bak` 成功
- [ ] **A6** 主档与 `.bak` 全损坏时拒绝加载且不删除文件
- [ ] **A7** `SaveVersion` 高于程序 → 拒绝；低于 → 迁移链逐级通过（每级有单测）
- [ ] **A8** 迁移链中途失败 → 原档不变
- [ ] **A9** 磁盘只读时保存失败并显著提示，旧档完好
- [ ] **A10** 存档体积 ≤ 120 KB（满载：12 田 + 500 字谱 + 8 手牌）
- [ ] **A11** 云存档路径：单文件、无绝对路径引用（供 M2 直接同步）
