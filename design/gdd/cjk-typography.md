## 概述

这个游戏**整个视觉就是在排字**。字体不是 UI 细节，是美术主体。

P4 解决三件事：**用哪些字、怎么渲染、怎么竖排**。其中字体授权是**法律风险**而非美术选择，必须在写第一行代码前定死——用了不可商用的系统字体打包发售，是上架前最典型的翻车方式。

---

## 玩家幻想

> **「这些字是写上去的，不是印上去的。」**

- 墨要有浓淡、笔要有飞白，但**不能模糊到读不出**。
- 农书翻页时，竖排的字应该像手抄本，不像表格。
- 大字（合字瞬间）要撑得住全屏，小字（HUD）要读得清。

## 详细设计

### 核心规则

**R1 · 字体授权（法律硬约束）**

| 字体 | 授权 | 可商用 | 可打包 | 结论 |
| --- | --- | --- | --- | --- |
| 思源宋体 Source Han Serif | SIL OFL 1.1 | ✅ | ✅ | **正文首选** |
| 思源黑体 Source Han Sans | SIL OFL 1.1 | ✅ | ✅ | HUD 备选 |
| 系统字体（苹方/微软雅黑） | 系统授权 | ❌ | ❌ | **禁止打包** |
| 明代刻本/书法字商业字体 | 各家 | 需购买 | 视合同 | 仅在预算允许时考虑 |

**硬规则：仓库内只能出现 SIL OFL / Apache 2.0 等明确允许嵌入打包的字体文件，并保留 LICENSE。** 任何"从本机拷一个字体"的做法在代码评审时直接拦下。

**R2 · 字符集策略（避免字体包爆体积）**

```
三层：
1. 白名单子集（300–500 字）—— 构建期预生成，覆盖所有字表条目与农书
2. UI 固定字（约 300 字：数字、标点、菜单文案常用字）—— 预生成
3. 动态补充 —— 运行时遇到未覆盖字符时生成 SDF 图集
```

- 禁止把整个 CJK 字库（>20,000 字）打进包。
- 字体图集上限 **2048×2048**，超出则新建图集页。
- 字形资产进 Addressables，**分包加载**（P3 农书独立一组）。

**R3 · 渲染管线（Unity 6000.6，⚠️ 待验证）**

- 路线 A（主）：TextMeshPro + 动态 SDF 图集。
- 路线 B（备）：UI Toolkit 文本组件（若 6000.6 已支持 CJK 动态图集）。
- **第 1 周必须验证**：中文动态图集在 6000.6 下是否正常生成、无缺字、无模糊；否则整条 UI 层要换方案。

> 这条是整个项目最大的**技术未验证项**，也是 `docs/engine-reference/unity/VERSION.md` 人工核对清单里排第一的项。

**R4 · 竖排规则**

- 竖排仅用于**农书条目**与**字条**；HUD 一律横排（竖排数字几乎不可读）。
- 实现：TMP 无原生竖排 → 用自定义 `VerticalLayoutGroup` + 逐字排布，注意：
  - 标点（，。——）需按 CJK 竖排规则摆放（句号在右上）
  - 数字与英文竖排时旋转 90°
  - 行距 ≥ 1.15 倍字高

**R5 · 字号与可读性**

```
最小正文字号：16 px @ 1080p
合字大字：>= 120 px @ 1080p
农书竖排：20–24 px
```

- 字号可缩放（M5），至少两档（100% / 125%）。
- **对比度**：墨色文字在宣纸底上，对比度不低于 4.5:1。

**R6 · 笔触与墨感**

- 字体提供字形骨架，**墨感靠 shader**：边缘墨晕、入笔/收笔的粗细变化、飞白（纹理遮罩）。
- 禁止用"整字图片"做动画（工作量爆炸），一律用字体 + shader + 顶点变形。

### 状态和转换

无状态。属静态资源与渲染管线。

## 公式

```
预生成字符数 ≈ 500（字表）+ 300（UI）+ 300（标点/数字/英文）
SDF 图集：2048×2048，单页约容纳 1000 个 32px 字符
预期 2 页以内
```

## 边缘情况

| # | 情况 | 处理 |
| --- | --- | --- |
| E1 | 运行时遇到未预生成字符 | 动态生成进图集；若图集满则新建页，并记录日志（便于构建期补全） |
| E2 | 英文/日文混排 | 英文用同族 OFL 字体；日文若不做，UI 走英文，避免字体缺口 |
| E3 | 竖排遇到长英文词 | 整词旋转 90°，不逐字旋转 |
| E4 | 缺字（字体不含该字形） | 回退到系统字体**仅用于显示**，且**不得进包**；同时记录告警 |
| E5 | 字体图集内存占用过高 | 上限 4096×4096；超限拒绝生成并告警 |

## 视觉/音频需求

- 合字瞬间的大字必须**撑满且不糊**——它是全游戏最强的视觉奇观。
- 农书竖排要有"手抄本"的行气，不是网格对齐。
- 细则归 P5。

## UI需求

- 所有文本组件必须走同一字体资产与 shader 变体，禁止局部用位图字。
- 中英文混排时基线对齐。

## 验收标准

- [ ] **A1** 仓库内所有字体为 SIL OFL / Apache 2.0 等允许打包的授权，且 LICENSE 文件在库
- [ ] **A2** 无系统字体被打包（构建产物内检查）
- [ ] **A3** 6000.6 下中文动态 SDF 图集正常生成，500 字全渲染无缺字（第一周技术验证）
- [ ] **A4** 图集页数 ≤ 4，总显存可控（1080p 下 < 64 MB）
- [ ] **A5** 竖排：标点位置、数字旋转、行距符合 CJK 规则（人工验收）
- [ ] **A6** 合字大字 ≥ 120px 时不模糊（SDF 缩放测试）
- [ ] **A7** 字号缩放 125% 下无布局溢出（与 M5 联合）
- [ ] **A8** 对比度 ≥ 4.5:1（取色验收）
