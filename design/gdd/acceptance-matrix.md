# 验收矩阵（Acceptance Matrix）

> **状态**: v1.0
> **用途**: 把散在 17 份 GDD 里的验收项汇总成**一份可执行的账本**，并补上系统之间的集成验收。
> **原则**: 能机器验证的绝不靠口头；必须人工的**明确标出来**，不许含糊。
> **最后更新**: 2026-11-17

---

## 1. 验收分五层

| 层 | 验证什么 | 手段 | 谁提供 |
| --- | --- | --- | --- |
| **L1 数据** | 字表、部件池是否合法 | `dotnet run --project Tools/validate-chartable` | F1 A1–A8 |
| **L2 单元** | 每个系统的规则对不对 | EditMode 测试 / `dotnet test` | 各系统 A 项 |
| **L3 集成** | 系统之间一起跑对不对 | 模拟层端到端脚本 | **本文件 §4（新增）** |
| **L4 平衡** | 数值是否成立 | `dotnet run --project Balance -- --runs 100` | M4 A4 |
| **L5 表现** | 看得懂、手感对 | **人工**（截图/走查/试玩） | 见 §5 |

> L1–L4 必须全绿才能进 Production。L5 可在 PreProduction 内逐步补。

---

## 2. 编号规范（从本文件起强制）

**跨文档引用一律用限定 ID：`<系统>-A<n>`**

| 写法 | 是否正确 |
| --- | --- |
| `F1-A3`、`C3-A12`、`M4-A4` | ✅ 唯一，可跨文档引用 |
| `A12`（在多份文档里都存在） | ❌ 无法定位 |

各 GDD 内部的裸编号保持不变（避免大规模重写），**但任何跨文档引用必须加系统前缀**。

## 4. 集成验收（新增 · 此前缺失）

> 这些**无法被任何单个系统的验收覆盖**。它们是 Sprint 01 第 4 周与进 Production 前的必过项。

| ID | 验收项 | 依赖系统 | 手段 |
| --- | --- | --- | --- |
| **I1** | 不启动渲染，跑完整一整季（7 回合 + 至少 1 次祟夜） | F2/F3/C1–C7/G4 | 控制台端到端 |
| **I2** | 不启动渲染，跑完整一局（四季 28 回合）无异常、无死锁 | 全部 | 控制台端到端 |
| **I3** | 同种子两局端到端 `final_hash` 一致 | F2/F3 | 双跑比对 |
| **I4** | 存档往返后继续跑，结果与不中断完全一致 | F4 + 全部 | 三段比对 |
| **I5** | 真实发牌下连续 200 回合，**0 次死手、0 次死锁** | C2/C3/C1 | 长跑统计 |
| **I6** | 春季能稳定凑出 **6–8 战意点**（50 条字表可达成性） | F1/C2/C7 | 策略模拟 |
| **I7** | 首次开垦回本 **≥ 1 回合**（Q5 修正后） | C1/C5 | 经济模拟 |
| **I8** | 健康玩法下一季祟夜 **1–2 次**；偷懒玩法显著更多 | C6/C7 | M4 策略对照 |
| **I9** | 全田为祟字局面下，靠兜底机制可在 3 回合内恢复可玩 | C3/C1/C6 | 故障态用例 |
| **I10** | 17 个系统的全部 A 项通过后，才允许 `stage.txt` 写 Production | 全部 | 人工汇总 |

**I7 现在是红的**：C5 的 §4.3 算出首次开垦只需 0.3 回合收入（悬置项 Q5），**这一条必须先改数值才能通过**。

## 5. 必须人工验收的项（已知全部）

| 项 | 内容 | 判据 |
| --- | --- | --- |
| P1-A8 | 成功/失败反馈不看颜色也能区分 | 灰度截图，让第三方指认哪次成功 |
| P4-A5 | 竖排标点、数字旋转、行距合规 | 与 CJK 规范对照 |
| P4-A3 | 50 字全渲染无缺字/糊边 | 16px 与 120px 截图 |
| P2-A7 | 明确列出的 5 项"不做"确实不存在 | UI 走查 |
| P7-A2 / P7-A8 | 主菜单仅 4 项；无开场 CG | 走查 |
| C4-A10 | 每个模板有"看形知效"的表现资源 | 与 P5 联合 |

> 人工项集中在表现层，这是正常的。但**它们不能替代 L1–L4**——先用机器把逻辑锁死，再用人眼判断好不好看。

## 6. MVP 总验收门（进 Production 前）

全部打勾才允许推进：

- [ ] L1：50 条字表通过 `validate-chartable`
- [ ] L2：17 个系统的 A 项全绿（约 170 条）
- [ ] L3：I1–I10 全绿
- [ ] L4：M4 三种策略 `hold_rate` 满足门槛（勤奋 ≥80% / 偷懒 30–50% / 莽夫 ≤15%，差值 ≥30 点）
- [ ] L5：§5 的人工项全部通过
- [ ] 缺口清零：`systems-index.md` §7 的悬置项全部关闭或明确降级

**当前状态**：L1 未跑（JSON 未经机器校验）、L2–L5 未开始。**17/17 系统"设计完成"≠"验收通过"**——这是两个完全不同的状态，别混。

## 7. 怎么跑

```bash
# L1
dotnet run --project Tools/validate-chartable

# L2（Sim 层单测）
dotnet test

# L3（集成）
dotnet run --project Balance -- --mode integration --runs 1

# L4（平衡）
dotnet run --project Balance -- --runs 100

# L5（人工）——见 §5 表格逐条走
```
