## 1. 概述（一段摘要）

《田字格》是一款**汉字合字驱动的江南水乡经营游戏**。玩家回到一座被祟祸侵蚀的水乡圩田，能用的只有一支笔：把偏旁拖进田里合成汉字，字的含义决定这块田产出什么、长出什么、挡住什么。字生田，田生字——收到田里的产出会化作新的偏旁，让你写出更复杂的字。白天你写字，让荒田重新有名字；夜里祟顺着水口进来，你白天写下的每一个字就是今晚的防线。一季六到八轮，四季之后，写出你的《农书》。

**电梯演讲（10 秒测试）**：在一片会说话的水乡田里，你用合字给土地下指令——写对了，庄稼长成你写的样子；写错了，字会活过来咬你；写得够好，全村的人才守得住一夜祟。

## 2. 玩家幻想

> **「这片水乡认我的字。」**

玩家希望自己成为：**一个用文字重新养活一片土地的守田人**——不是战士，不是英雄，是一个字写得越深、田就越肥、人就越愿意留下的人。
每个机制必须服务这条幻想：字是玩家的手，土地是玩家的画布，村民与字灵是玩家的话筒与回音。凡是不服务于"我写的字改变了这片地方"的机制，删掉。

## 3. 核心循环

### 3.1 30 秒循环（每时每刻）

> **拖两个偏旁进田 → 合成汉字 → 田按字义产出 → 收获化作新偏旁 → 写更复杂的字**

- 底部是**偏旁池**（自动补充的手牌，容量有限）。
- 场上每块**田 = 一个字格**。把部件拖进去，合成有效汉字即生效；合成失败则变成一团**祟字**（占格、积祟气、招来祟）。
- 字的产出必须**一看就懂**：秋（禾+火）= 全场立即成熟；男（田+力）= 多一个劳力；休（人+木）= 休耕，恢复地力；明（日+月）= 祟夜里照亮隐身的东西。
- 动作本身即有趣：拖拽→合字→生效是「顿悟 + 面板变化」的双重反馈，水墨字形的变形与泼溅承担视觉爽感，不依赖数值。

### 3.2 5 分钟循环（一次农事轮）

1. 领到本轮的偏旁手牌。
2. 在有限田块内布字（有产出型、地力型、防御型、关系型四类）。
3. 收获结算：金币（铜钱）、偏旁、地力变化。
4. 祟气结算 → 可能触发祟夜。
5. 进入下一轮，手牌重置。

**选择在哪里发生**：田块数量固定且小（初始 6 块），所以每写一个字都是"从别处挪走一个机会"。这是从《赵云与阿斗》继承的**槽位稀缺**，但落在土地上，不再落在兵营里。

### 3.3 会话循环（30–120 分钟 = 一季）

- 一季 = 6–8 轮农事 + 1–2 场**祟夜** + 季末结算。
- 季末：结算村民去留、解锁新田块/新偏旁池、字灵结契、**季节不可回退**。
- 停止点天然存在于季末。不玩时玩家想的是"下一季我该先写哪个字"。

### 3.4 长期成长循环（一局四季）

- **成长单位 = 认识的字**。组成过的字进入《农书》（字谱），成为可反复调用的东西，也是图鉴。
- 领地扩张：荒地 → 熟田 → 圩田，田块 6 → 12（上限）。
- 村民回归：从空村到 8 人。
- 通关条件：写完四季并守住最后一场大祟，完成《农书》。

## 4. 支柱与边界

### 4.1 四条支柱

| # | 支柱 | 一句话定义 | 设计测试（争论时以此裁决） |
| --- | --- | --- | --- |
| P1 | **字即是手** | 汉字是唯一操作手段，不是界面装饰 | 若某功能可以"点一下按钮"做到 → 砍掉按钮，必须组字 |
| P2 | **认得就是得到** | 成长的单位是"字"，不是百分比 | 争"产量 +20%" 还是"多认识一个字" → 选字 |
| P3 | **水乡会说话** | 世界、字灵、祟都有性格，失败要好笑不要冰冷 | 该弹红字警告吗 → 让字灵阴阳怪气地骂你 |
| P4 | **一季不回头** | 时间不可逆，代价可感 | 该允许回档重来吗 → 不允许 |

支柱之间的张力（故意保留）：P1 要求玩家做"合字决策"，P4 要求决策有不可逆代价，而 P3 要求惩罚是好笑的——**好笑与不可逆同时成立**，是这个游戏最难也最值钱的地方。

### 4.2 反支柱（明确不做）

- **不做字典/教学游戏**：只用手写白名单内的常用字（上限 300–500 字），不考冷僻字、不考字义知识。
- **不做战斗系统**：没有血条、没有攻击动画、没有可控角色。冲突只通过田地状态与字阵表达。
- **不做开放世界**：一个圩、一年、一辈子。
- **不做实时联机 / PvP**：见 §9 否决项。
- **不做历史剧与配音**：江南是氛围，不是考据。

## 5. 关键系统（概念级）

### 5.1 田格与字谱

- 田块 = 字格 = 唯一选择空间。初始 6 块，上限 12 块。
- 字生效生命期 = 一季；季末统一"洗田"，但**字留在《农书》里**（永久知识，不永久产出）。
- 字谱按部首/字族组织，玩家看到的不是列表，是一本可以翻的农书。

### 5.2 祟气与祟夜（外部入侵压力）

- **祟气**：每轮累积，来源为祟字、长时空田、过度扩张；休耕与"守字"可降低。满值（初值 12）触发祟夜。
- **祟夜**：字格锁定，祟从圩外水口沿固定路径进入。玩家不做即时操作，而是用**白天写好的字阵**迎敌。
  - 这条设计是整个概念的关键：**白天的经营质量直接决定夜里守不守得住**，因此"发展家园"和"抵御入侵"不是两套系统，而是同一套。它同时满足"不增加实时操作复杂度"（单人可做）与"有真实外部压力"。
- 祟夜结局：守住 → 掉落祟字残片（稀有偏旁）+ 村民信心上升；漏祟 → 毁田、地力归零、**村民离开一个**。

### 5.3 村庄合力（对"齐心协力"的单机实现 · 本文件最重要的判断）

> **判断（已由创意总监决议）**：先做**单机的村庄合力**，但**架构必须为联机留口**——不是"上市后推倒重做"，而是从第一行代码起就让合作模式"接上网络层即可，不必改设计"。

三条落地机制：

1. **村民即人力**：村民是具体的人，有名字、有脾气，会累会偷懒，会记住你上次把他派去堵最险的堤口。
2. **村民会学你的字**：你写过的字会被村民学会；祟夜时他们自动用学到的字守自己的田。**"齐心合力"的具体机制表达 = 你教的字变成了别人的防御。**
3. **经营即防御**：村民留下需要理由（有田种、有屋住、有字学）。人在，夜才守得住；人走，地就荒——发展家园本身就是防御力。

### 5.4 联机留口的架构约束（不可协商 · 选引擎前必须生效）

这一段不是"以后再说"，是**现在就约束技术选型的四条硬要求**。任何一条做不到，就等于把合作模式钉死在重写上。

1. **模拟与表现分离**：全部游戏状态（田块、字、祟气、村民）住在一个纯数据层里，不引用任何渲染/UI/引擎节点。表现层只读状态、发命令。验收方式：不启动渲染也能跑完一整季。
2. **确定性 tick + 命令式输入**：一次农事轮由固定步长推进，玩家操作表达为"命令"（写字段 X、拖偏旁 A+B 到田 Y），而不是直接改状态。这是日后改网络同步、回放、作弊校验的唯一低代价路径。
3. **存档 = 状态快照**：存档序列化整个状态层，不含引擎对象引用。联机模式下同一个存档结构就是房间状态。
4. **禁止全局单例与隐式单玩家假设**：`player` / `village` 一律作为实体参数传递，禁止写死"当前玩家"。规则层里出现任何"the player"的硬编码，都算架构债。

> 这四条同时**降低**单人版的风险：它们让平衡可自动化验证、让 bug 可复现、让"字阵胜负"能被脚本批量回归——正好是第一款游戏最缺的东西。

### 5.5 字灵

- 每季可与一只字灵结契，提供被动与"性格干预"（会讨价还价、会阴阳怪气、会在你写错字的时候笑）。
- 字灵是叙事载体：**零过场**，全部通过对话短句与田间反应表达。

## 6. 公式（初值，全部待调）

```
祟气增量：ΔQ = 1 + 2×空田数 + 3×祟字数 − 1×休耕田数
触发条件：Q ≥ Qmax（初值 12），触发后 Q 归零
祟夜敌力：E = (2.0 + 0.8×季序) × (1 + 0.15×已开垦田块数) × (1 + 0.1×扩张冲动值)
防力：  D = Σ(田字战意) × (1 + 0.1×(村民数 − 5)) × 季相系数
战意取值：产出型 1 / 防御型 3 / 地力型 2 / 关系型 2（会意字按字义归类的可读规则）
判定：  D ≥ E → 守住；否则被毁田数 = ceil((E − D) / 3)，且村民 −1
```

**平衡意图**：`已开垦田块数` 进入敌力公式，意味着**扩张越快，祟越强**——你要发展，就必须承受压力。这正是"外部入侵压力促使玩家发展家园"的数学表达。

## 7. 边缘情况

- 全部田块为空 → 祟气暴涨 → 强制祟夜（不能靠"什么都不做"苟过去）。
- 手牌里没有任何可组成的偏旁 → 允许"糊字"（随机有效弱字），保底不卡死。
- 玩家连续两季漏祟 → 村民降至下限（2 人），进入"残季"状态：**敌力上压、每波多毁一块田**，给翻盘的窄路而不是直接 Game Over。
  > **v0.3.1 更正**：原文写"田块缩减"，与 C1 的 4×3 = 12 格固定布局冲突（田块是固定索引的，删格会破坏存档与邻接）。已改为"敌力上压 + 毁田数 +1"，见 [G4 季相](season-cycle.md) R7。
- 同一字重复写入多块田 → 允许，但同类字的战意与产出按 `0.8^n` 递减（避免"一招通关"退化策略）。
- 已在《农书》里的字 → 免试直接用（这是"认识"的兑现，也是玩家愿意反复玩的理由）。

## 8. 依赖关系与调整旋钮

**系统依赖（概念级，待 `/map-systems` 细化）**

```
字格与田块 ──┬─→ 字谱/农书 ──→ 村民学习 ──→ 祟夜防力
             ├─→ 偏旁池（手牌）──→ 合字校验（白名单）
             └─→ 祟气 ──→ 祟夜 ──→ 毁田/村民去留 ──→ 回到田块
经济（铜钱/地力）──→ 田块开垦 ──→ 祟夜敌力（扩张冲动）
字灵结契 ──→ 被动加成 / 叙事反馈（不影响核心判定，只调风味）
```

**调整旋钮**：`Qmax`（祟夜频率）、`E` 的三个系数（难度曲线）、战意表（字类强度）、`0.8^n` 重复惩罚、田块上限、村民下限、手牌容量与补牌速度、白名单字数。

## 10. 目标平台、受众与竞品差异

- **平台**：PC / Steam，键鼠优先，手柄与云存档为上架必需项。
- **受众**：喜欢江南美学与汉字趣味的经营玩家；被《中国式家长》《了不起的修仙模拟器》一类"中式题材 + 独特系统"吸引的中文玩家。**明确不服务**：追求操作爽感的动作玩家、需要高强度叙事的剧情玩家、非中文首次接触汉字的玩家。
- **竞品差异**：《种田+塔防》类（含自己的原型）差异在"冲突不独立成系统"；《汉字题材》类差异在"字是操作而非题材"；《牧场物语/星露谷》类差异在"内容靠规则组合而非手工内容"。**一句话差异**：别人用塔守家，你用字守家，而字是从自己田里长出来的。

## 11. 范围与里程碑（一个人 9–12 个月）

| 阶段 | 时间 | 产出 | 通过标准 |
| --- | --- | --- | --- |
| **可行性原型（生死关）** | 第 1 个月 | 3 块田 + 60 字白名单 + 1 季 + 1 只字灵 | **只验一件事：合字本身体验好不好。** 不通过就停，不投美术 |
| 纵向切片 | 第 2–6 个月 | 春夏两季完整、150 字、祟夜、农书 UI | 能连续玩 2 小时不腻；有 3 条以上不同解法 |
| 内容生产 | 第 7–10 个月 | 四季、300+ 字、3–5 字灵、12 田块 | 通关 6–8 小时，全字谱 12–15 小时 |
| 上架 | 第 11–12 个月 | 商店页、预告片、中英日、成就、手柄、存档 | 能上架并跑通退款率与好评率观察 |

**MVP 定义（用来回答"核心循环是否有趣"的最小构建）**：3 块田、60 字、1 季、2 场祟夜、无字灵。**在此之外的一切都是可延后项。**

## 12. 验收标准

- [ ] 核心循环可在 **30 秒内**讲清（"字生田，田生字"），且听完的人能复述三步。
- [ ] 支柱能真的用来砍功能：至少有一次，争论以 P1–P4 之一裁决而不是"两个都做"。
- [ ] 存在明确的"不做什么"清单（§4.2 + §9），且已被用来拒绝至少一个提案。
- [ ] 技术上无未解死结：合字校验靠白名单表实现，无需 NLP；2D 水墨管线可行。
- [ ] 可行性原型在 1 个月内给出"继续 / 停止"的明确结论。
