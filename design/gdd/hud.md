## 概述

P2 决定玩家**能看见什么**。这个游戏的信息密度不低（祟气、铜钱、地力、战意、剩余回合、手牌可用性），但基调是"慢、静、好看"。

所以 P2 的核心任务不是"把信息都放上去"，而是**分层**：哪些必须常驻、哪些悬浮才给、哪些永远不显示。**少一样东西往往比多一样更能保住氛围。**

---

## 玩家幻想

> **「我不用找数字，它在田里。」**

- 地力应该从**土地的样子**看出来，而不是从进度条。
- 敲下第一个字的时候，玩家不该被教程弹窗挡住。
- 界面应该像**一本摊开的农书**，不像仪表盘。

---

## 详细设计

### 核心规则

**R1 · 信息分三层**

| 层 | 内容 | 呈现方式 |
| --- | --- | --- |
| **常驻**（始终可见） | 祟气、铜钱、季/回合、手牌 | 底栏与顶部角落，克制、低对比度 |
| **悬浮**（指向才给） | 田块详情（状态/地力/字/战意/剩余回合）、手牌详情 | 田块旁浮出小卡，不遮邻田 |
| **专属屏**（时刻触发） | 祟夜预览、季末结算、通关 | 打断式，且**只在关键节点** |

**R2 · 祟气必须常驻，且以环境为主载体**

- 常驻一条细刻度（距 `Qmax` 的倒数），同时环境承担主要表达（雾、虫鸣、天光，见 C6 视觉需求）。
- 预警态（`Q ≥ 9`）必须在刻度上体现"还差几步"。

**R3 · 地力画在地里，不画进度条**

- 地力用田块本身的质感表达（湿润/干裂、颜色深浅）。
- 悬浮卡里才给数字（0–100）与"这块还值多少钱"。

**R4 · 祟夜预览屏（硬需求，关闭悬置项 Q7）**

祟夜开始**前**必须给一屏结算预览：

```
本夜崇气已满
当前防力 D = 5.4       （含村民系数、季节系数）
预计敌力 E ≈ 5.6（三波：1.7 / 2.0 / 2.0）
场上战意来源：林×2(+6) 明×1(+1)   [共 7]
⚠ 缺口 0.2 → 预计毁田 1 块（最可能：index 8）
[ 迎战 ]
```

**没有这一屏，祟夜就从"算账"退化成"掷骰子"**，这是 C7 的核心乐趣所在。

**R5 · 拒绝与提示：轻量、不打断**

- `locked` / `occupied` / `not_enough_parts` 一律用**田块旁的一行小字 + 轻微抖动**，不用弹窗、不用红框。
- 提示文字由 P3 的字灵口吻提供（"今晚写不了"），不是"错误：操作无效"。

**R6 · 明确不做的东西**

| 不做 | 原因 |
| --- | --- |
| 小地图 | 一屏之内看得完，加了只是噪音 |
| 任务/目标追踪面板 | 目标是玩家自己的，不派任务 |
| 弹窗式新手教程 | 用第一个字的"代合"来教（见 P8） |
| 伤害/产出飘字连击 | 破坏水墨氛围，改成一次汇总动效 |
| 数值成长曲线图 | 经营游戏不需要让玩家看函数 |

**R7 · 中文字排版依赖**

- 所有文案走 SDF 动态字体图集（P4），**禁止**在 HUD 里用位图字。
- 竖排用于"农书"与"字条"，**横排**用于 HUD（竖排数字极难读）。

### 状态和转换

```
Normal --[指针悬停田块]--> Inspecting --[移开]--> Normal
Normal --[Q 达 Qmax]--> NightPreview --[迎战]--> NightResolving --[结束]--> Normal
Normal --[回合耗尽]--> SeasonEnd --[确认]--> Normal
```

## 公式

### 4.1 常驻区布局预算

```
底栏高度：<= 96 px（1080p）
顶部角落：祟气刻度 + 季/回合
手牌区：<= 8 张，单张 <= 96 px 宽
田块浮卡：不超过 240 px 宽，且不得遮挡超过 1 个邻田
```

### 4.2 崇夜预览的估算来源（只读）

```
D_display = C7.D_calculate(state)          // 与实算同一函数，禁止第二套
E_display = C7.E_estimate(state)           // 区间显示：min..max（若含随机）
```

> **硬约束**：预览与实算必须调用**同一个函数**。两套公式必然漂移，玩家会发现预览骗人，然后不再相信任何数字。

## 边缘情况

| # | 情况 | 处理 |
| --- | --- | --- |
| E1 | 田块极多时浮卡遮挡 | 浮卡自动翻转方向（左/右/上），保证不遮当前田 |
| E2 | 释放期间无 `Char` 田（D = 0） | 预览屏必须明确说"今晚无字可守"，而不是静默显示 0 |
| E3 | 祟气已达 Qmax 但仍在本回合操作中 | 祟气刻度进入"已满"态，提示"本回合结束后迎战"，不提前打断 |
| E4 | 文字量超出浮卡宽度 | 省略号 + 悬浮"完整字条"入口；不换行撑爆布局 |
| E5 | 4K/超宽屏 | UI 用锚点与安全区适配，底栏不随宽度拉伸 |
| E6 | 存档加载失败 | 用 F4 的具体原因提示，不吞错 |

## 视觉/音频需求

- HUD 与场内**必须同一套毛笔规范**（概念 §9 的美术风险缓解）。
- 常驻元素要"退后"：低饱和、细笔、不加投影。
- 数值变化用轻微上浮消失，不用数字滚动。
- 细则归 P5 / P6。

## UI需求

- 键鼠/手柄图标动态切换（与 P1 共享逻辑）。
- 全部文案支持中文与英文（P4/M3），预留 30% 宽度余量。
- 字号可缩放（M5），至少两档。

## 验收标准

- [ ] **A1** 三层信息全部实现；常驻区无遮挡田块（1080p 与 4K 各验一次）
- [ ] **A2** 祟气常驻可见且预警态显示倒数
- [ ] **A3** 地力不出现在常驻进度条上（只有田块质感 + 悬浮数字）
- [ ] **A4** 祟夜预览屏存在，且 D/E 与实算**调用同一函数**（用 mock 校验调用计数）
- [ ] **A5** 预览屏在 D=0 时明确提示"今晚无字可守"（E2）
- [ ] **A6** 拒绝类提示不弹窗、不红框，时长 ≤ 1.2s
- [ ] **A7** R6 列出的 5 项"不做"确实不存在（UI 走查）
- [ ] **A8** 浮卡不遮挡当前田与其任一邻田（E1）
- [ ] **A9** 超宽屏与 4K 下无横向溢出
- [ ] **A10** 文案在 8 张手牌满载时仍不溢出（中文/英文各验）
