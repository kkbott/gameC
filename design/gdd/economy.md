## 概述

C5 管两样东西：**铜钱**（可花，建设与止损）和**地力**（不可花，产能基线）。

它接收 C4 交出的 `YieldModifier[]`，把它换算成铜钱；同时负责地力的消耗与恢复。它是"效率与可持续"之间那个唯一的平衡点——**玩家贪产就会把地写瘦，写瘦了又得休耕**，这个节奏是本作最核心的经营张力。

**C5 不决定"字有多强"**（C4 管），**不决定"祟气多高"**（C6 管）。它只回答：这一回合，这片地给你多少钱，以及你透支了多少地力。

---

## 玩家幻想

> **「地是要养的。」**

- 连种三季高产的玩家，第四季会发现地已经硬了——**不是因为系统惩罚他，而是因为他把地写瘦了**。
- 休耕一季的玩家会有点肉疼（少赚了一季），但下一季地力回满时会有"回本"的踏实感。
- 铜钱应该**总是紧的**。第一次开垦、第一次清祟字、下一次开垦之间永远差一点点——这是经营游戏的心跳。

## 详细设计

### 核心规则

**R1 · 两个货币，两种性质**

| 资源 | 性质 | 获取 | 消耗 | 能否恢复 |
| --- | --- | --- | --- | --- |
| **铜钱** `Money` | 可花，只增不减（除支出） | 产出结算、祟夜守住奖励 | 开垦、清祟字 | 可赚回 |
| **地力** `Soil` | 不可花，产能基线，0–100 | 自然恢复、休耕 | 每次产出 | 缓慢恢复 |

**R2 · 产出结算（挂在 F2 R5 第 2 步）**

```
1. C4 交出 YieldModifier[]：{ plotIndex, multiplier }
2. C5 对每块有产出的田：
     gold = round( baseGold(soil) × multiplier )
3. Money += Σ gold
4. 对每块产出的田：Soil = max(0, Soil − SOIL_COST_PER_YIELD)
5. 未产出但未休耕的田：Soil = min(100, Soil + SOIL_RECOVER_NATURAL)
```

**R3 · 产出基数由地力决定**

```
baseGold(soil) = 6 + floor(soil / 20) × 2
               soil 0   → 6
               soil 100 → 16
```

> 地力不是"产量百分比加成"，而是**绝对基数**。这样玩家能直接算出"这块地现在值多少钱"，可读性优先于数学优雅。

**R4 · 地力消耗与恢复**

```
SOIL_COST_PER_YIELD    = 8      每产出一次 −8
SOIL_RECOVER_NATURAL   = 3      每回合自然 +3
fallow_restore 模板     = 直接回满 100（C4 触发，C5 执行）
```

**净账（一块田连续产出）**：每回合 −5 地力 → 100 → 0 需要 20 回合。一季 6–8 回合，所以**单季内不会见底，但跨季会累积**。这正是我们想要的：地力管理是**跨季决策**，不是单季微操。

**R5 · 铜钱去向（MVP 范围）**

| 支出 | 成本 | 归属系统 |
| --- | --- | --- |
| 开垦田块 | 25 / 35 / 50 / 65 / 85 / 110 | C1 |
| 清除祟字 | 3 铜钱 / 个 | C3 |

**明确不做**：不做维护费、不做税收、不做建筑升级、不做市场波动。第一款游戏，两个支出项已经足够制造紧迫感。

**R6 · 收入来源（MVP 范围）**

| 来源 | 数量 | 归属 |
| --- | --- | --- |
| 字效产出 | 见 R2 | C4 → C5 |
| 祟夜守住奖励 | 一次性，随季递增 | C7 触发，C5 执行 |
| 开局 | 90 铜钱 | 初始化 |

**R7 · 铜钱不为负**

任何支出命令在 `Validate` 阶段检查余额，不足即拒绝（走 F2 的 `CommandRejected`）。**不存在负债**——本作不做金钱破产，只做"没钱就停手"。

### 状态和转换

C5 自身无独立状态，读写 `FarmState.Money` 与 `Plot.Soil`。

**地力的三档语义**（供 UI 与玩家心智使用）

| 区间 | 语义 | 玩家感受 |
| --- | --- | --- |
| 80–100 | 熟田 | 值钱，舍不得休 |
| 30–79 | 疲田 | 有点亏，开始想休耕 |
| 0–29 | 瘦田 | 必须休耕，否则白种 |

**一次回合结算的完整时序**

```
RoundResolveCommand (F2 step 2)
  → C4 收集 YieldModifier[]
  → C5 逐田计算 gold、扣地力
  → 自然恢复未产出田
  → Money 写入 FarmState
  → 发 ProductionSettled 事件（P5 播金币动效）
```

### 与其他系统的交互

| 系统 | 方向 | 接口 | 所有权 |
| --- | --- | --- | --- |
| C1 田块 | 上游 | 读 `PlotStatus` / `Soil` / 已开垦数 | C1 拥有布局 |
| C4 字效 | 上游 | **接收** `YieldModifier[]` | C4 判强度，C5 换钱 |
| F3 状态层 | 上游 | `Money` / `Plot.Soil` | F3 拥有存储 |
| F2 步进 | 上游 | 结算顺序第 2 步 | C5 挂在固定顺序上 |
| C6 祟气 | 下游 | 不直接交互（崇气不吃钱） | — |
| C7 祟夜 | 下游 | 守住奖励金额；摧毁田时 `Soil −50` | C7 判定，C5 执行扣减 |
| C3 校验 | 下游 | 清祟字扣款；余额校验 | C3 触发，C5 执行 |
| P2 HUD | 下游 | 显示铜钱、地力、差额提示 | — |

## 公式

### 4.1 单田产出

```
baseGold(soil) = 6 + floor(soil / 20) × 2
gold(plot)     = round( baseGold(soil) × yieldModifier )
yieldModifier  = C4 §4.1 给出
```

### 4.2 地力

```
产出后：  Soil = max(0, Soil − 8)
自然恢复：Soil = min(100, Soil + 3)
休耕：    Soil = 100（fallow_restore）
祟夜摧毁：Soil = max(0, Soil − 50)
```

### 4.3 平衡意图数值表

| 场景 | 每回合铜钱 | 说明 |
| --- | --- | --- |
| 开局 6 田、地力 100、纯基础产出 | 6 × 16 = 96 | 上限参考 |
| 开局实际（需布字，字不齐） | 约 40–60 | 前 2 回合 |
| 12 田全熟 | 12 × 16 = 192 | 中期天花板 |
| 开垦回本 | 25 ÷ 96 ≈ 0.3 回合 | 极快，需观察 |

> **⚠️ 已知待调**：按此数值开垦回本过快（首次开垦仅需 0.3 回合收入）。这是 MO-1 问题，见开放问题 Q1。

## 边缘情况

| # | 情况 | 处理 |
| --- | --- | --- |
| E1 | 铜钱不足以支付任何操作 | 不破产、不负数；玩家仍可布字与过回合，靠产出恢复 |
| E2 | 地力为 0 的田继续产出 | 允许，`baseGold = 6`（不为负，不归零），但极不划算 |
| E3 | `fallow_restore` 的田同时被祟夜摧毁 | 先回满（step 2）再 −50（step 5），净 50（与 C4 E2 一致） |
| E4 | 同一回合多块田触发 `all_ripen` | `all_ripen` 每田只结算一次，不重复计入 |
| E5 | 祟夜守住奖励与产出同回合 | 两笔分别入账，事件顺序：产出 → 祟夜奖励 |
| E6 | 地力溢出（>100） | 封顶 100，不转换、不存储 |
| E7 | 存档中 `Money` 为负（旧档） | 加载时钳到 0 并记警告（E1 的正向修复） |

## 调整旋钮

| 旋钮 | 初值 | 安全范围 | 太高会怎样 | 太低会怎样 |
| --- | --- | --- | --- | --- |
| `baseGold` 基数 | 6 | 4–10 | 前期太宽松，紧迫感消失 | 前 3 回合什么都做不了 |
| `baseGold` 地力斜率 | 2 / 20 点 | 1–4 | 地力成为唯一追求，休耕强制 | 地力无关紧要，可持续性玩法消失 |
| `SOIL_COST_PER_YIELD` | 8 | 4–15 | 一季内就见底，被迫频繁休耕 | 地力永不掉，经营维度消失 |
| `SOIL_RECOVER_NATURAL` | 3 | 1–6 | 地力自愈太快，休耕无意义 | 只能靠休耕，容错太低 |
| 开局铜钱 | 90 | 60–150 | 前两回合太舒服 | 开局直接卡死 |
| 祟夜守住奖励 | 随季 +10 起 | 5–40 | 防守成为主要收入，种田意义下降 | 守夜不值得，玩家放任毁田 |
| 清祟字成本 | 3 | 1–8 | 清不起，祟字永久占格 | 随便清，占格惩罚消失 |

## 视觉/音频需求

- 产出结算要有**层级感**：单田小额直接飘字，多田同时则一次汇总动效（避免满屏数字）。
- 地力变化要用**土地本身的质感**表达（颜色、干裂程度），不能只靠数字条。
- 休耕的田在视觉上应该"安静下来"——不是灰掉，是变得朴素。
- 细则归 P5。

## UI需求

- 地力必须**在田块本身**可见（不必点开检查），因为它是玩家的核心预算。
- 铜钱差额提示（"还差 12 铜钱"）优先于余额数字。
- 地力低于 30 时，该田的产出预览用红色数字显示"这块地在亏"。

## 验收标准

- [ ] **A1** 产出 = `baseGold(soil) × yieldModifier`，四舍五入正确，无浮点累积误差
- [ ] **A2** 地力扣减与自然恢复按 R2 顺序执行；未产出田才自然恢复
- [ ] **A3** 地力钳制在 [0, 100]，两边都不溢出
- [ ] **A4** 铜钱永不为负：所有支出命令校验余额，不足即拒（与 F2 A5 联动）
- [ ] **A5** `fallow_restore` 回满 100；与祟夜摧毁同回合时净 50（E3 用例）
- [ ] **A6** `all_ripen` 多田触发时每田只结算一次（E4 用例）
- [ ] **A7** 结算总耗时：12 田全产出情况 < 2ms
- [ ] **A8** 静态检查：C5 内不出现 `template`/`tier` 判断（产出强度必须来自 C4 的 modifier）
- [ ] **A9** 存档往返后 `Money` 与各地 `Soil` 完全一致
