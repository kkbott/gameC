## 概述

C2 决定**玩家手上有什么**：一个容量 5 的偏旁手牌，每回合补牌，发牌时按"能不能凑成字"加权。

它是本项目**最高风险系统**——不是因为它复杂，而是因为一个发牌规则没调对，玩家就会"想写字却没有部件"，然后关掉游戏。F1 已经定义了可达性发牌的目标失败率（`f* = 0.20`），C2 负责把它落到实现。

---

## 玩家幻想

> **「我手里的牌，是我认识的字。」**

玩家不该感觉自己在抽奖。理想的手感是：

- 一眼扫过去，脑子里已经浮出两三种写法（"禾在手，等个火；田也有了，先写个男"）。
- 手牌变宽的感觉 = **学会更多字**，不是数值成长。
- 卡住的时候是"我想写的那个字凑不出来"，而不是"我什么都没有"——**卡在构想上，不卡在资源上**。

## 详细设计

### 核心规则

**R1 · 手牌的形态**

```csharp
public sealed class HandState
{
    public List<GlyphId> Tiles;     // 有序，位置固定，不自动排序
    public int Capacity;            // 初值 5，上限 8
    public List<GlyphId> DrawPile;  // 预生成的牌堆（确定性），非空时才洗牌
}
```

**R2 · 补牌规则（本系统的核心裁决）**

| 时机 | 动作 |
| --- | --- |
| 回合开始 | 补至 `Capacity` |
| **成功合字** | 补 **2** 张（正好抵消消耗的 2 个部件，净零） |
| **失败合字** | **不补**（净 −2） |
| 回合结束 | 不动（剩余手牌带到下回合） |
| 洗牌 | 牌堆空时用 F2 的 RNG 重洗，**洗牌结果进 `FarmState`** |

> **为什么要"成功补、失败不补"**（这是我在三个方案里裁的）：
>
> - **纯定量补牌**（每回合只补至容量）：5 格手牌一回合只够布 2–3 次字，而 C3 的公式假设每回合 6 次拖拽——**直接矛盾，回合会碎成渣**。
> - **成功即补满**（用掉就补回容量）：手牌只剩"当下选项"，失败不痛，C3 的"双部件消耗"惩罚归零。
> - **成功补 2 / 失败不补**：成功是净零（可以一直写下去，受田格限制），失败是净 −2（消耗的是**连续犯错的能力**）。
>
> 于是手牌容量限制的**不是动作次数，而是选项宽度**；失败消耗的**不是当前操作，而是未来的容错空间**。这正好让 C3 的"双消耗"有了真实分量。

**R3 · 从 C3 继承的矛盾修正**

C3 §4.1 写的"每回合 6 次拖拽、期望失败 1.2 次"在 R2 下成立：

```
6 次布字 = 12 个部件消耗
成功 4.8 次 × 补 2 = 补回 9.6
失败 1.2 次 × 补 0 = 补回 0
净变化 = −2.4 部件/回合
容量 5 → 连续两回合全败即见底
```

**C3 §4.1 的"每轮期望损失 2.4 部件"这句话现在是物理成立的**，不再是纸面估算。

**R4 · 发牌权重（可达性）**

```csharp
weight(g) = BASE_WEIGHT + λ × reachableTargets(g)
reachableTargets(g) = |{ t ∈ targets(g) : 另一半部件 ∈ Tiles ∪ 场上字 }|
BASE_WEIGHT = 1
```

- `λ` 由 F1 R4 的标定流程得出，目标失败率 `f* = 0.20`（C2 负责实测与标定）。
- **硬约束**：补牌完成后，若 `Tiles` 内不存在任何可成字组合，强制把一张替换为能配对成功的部件。
- **手感约束**：同一部件在手牌内的数量上限 = 2（防"五张全是禾"）。

**R5 · 部件的稀有度分层**

部件的出现基础权重与其稀有度挂钩，与 F1 R6 的 tier 判据同源：

| 层 | 基础权重 | 说明 |
| --- | --- | --- |
| 高频（田/火/木/日/人/土） | 3 | 构字骨架 |
| 中频（禾/艹/氵/月/力/子/女） | 2 | 有效但不万能 |
| 低频（工/石/十/木偏/山） | 1 | 高阶字的关键 |

**R6 · 容量的成长**

```
初始 Capacity = 5
每季末 +1，上限 8                     （长期成长，进存档）
hand_growth 模板：下一回合临时 +1      （不累计，回合序号标记）
```

**R7 · 牌堆与确定性**

- `DrawPile` 在季初一次性生成（用 F2 RNG），之后按顺序取。
- 洗牌**也消耗 RNG**，且洗牌后的牌堆必须写进 `FarmState`——否则回放会分歧。
- **禁止**任何"按当前帧/时间/句柄"的随机源。

### 状态和转换

```
RoundStart --[补至 Capacity]--> HandReady
HandReady --[成功合字, −2]--> HandReady --[+2]--> HandReady
HandReady --[失败合字, −2]--> Starved   --[回合末不补]--> Starved
Starved  --[NextRoundStart, 补至 Capacity]--> HandReady
DrawPile --[空]--> Reshuffle(用 RNG) --[写回 FarmState]--> DrawPile
```

| 系统 | 方向 | 接口 | 所有权 |
| --- | --- | --- | --- |

## 公式

### 4.1 补牌后手牌数量

```
onRoundStart:  Tiles = min(Capacity, |Tiles| + 补足量)   → 补至 Capacity
onComposeSuccess: Tiles += 2   (受 Capacity 封顶)
onComposeFail:    不变
```

> 注意：成功补 2 会受 `Capacity` 封顶，所以"手牌满时成功布字"实际是 −2 后 +2，净零；若手牌接近满，**补不进去的部分不溢出到牌堆外的"下次再给"**（避免隐藏账本）。

### 4.2 权重与失败率

```
weight(g) = RARITY_BASE[g] + λ × reachableTargets(g)
P(单次配对有效) = Σ_{有效对} weight 组合概率 ≈ 1 − f*
目标 f* = 0.20，区间 0.15–0.25
```

### 4.3 死手防护

```
afterRefill:
  if (!existsValidPair(Tiles)) →
       pick random tile t (RNG)
       replace t with g* where ∃ other ∈ Tiles : Lookup(g*, other) != null
```

## 边缘情况

| # | 情况 | 处理 |
| --- | --- | --- |
| E1 | 回合中手牌耗尽（`Tiles.Count < 2`） | 允许**提前结束回合**（命令 `EndRoundEarly`），下回合补满。不惩罚 |
| E2 | 牌堆空且手牌也不足 | 用 RNG 重洗全部部件生成新牌堆，写回状态 |
| E3 | 同一部件超过 2 张 | 补牌时若某部件已有 2 张，重抽（消耗 RNG，不影响确定性） |
| E4 | 洗牌后仍然死手 | 死手防护强制替换（§4.3），保证至少 1 组可成字 |
| E5 | `hand_growth` 与季末扩容同回合 | 临时 +1 叠加在季末 +1 之上，但临时效果只持续 1 回合 |
| E6 | 容量已达 8 仍收到 `hand_growth` | 无效（记日志），不溢出、不转成其他资源 |
| E7 | 牌堆生成后字表更新（新增字） | 牌堆按旧表生成也合法；新字下季才进池。**不做热更新** |
| E8 | 回放时 RNG 状态不一致 | 由 F2 的 `ReplayHash` 检出，说明实现有静态随机源——视为缺陷 |

## 调整旋钮

| 旋钮 | 初值 | 安全范围 | 太高会怎样 | 太低会怎样 |
| --- | --- | --- | --- | --- |
| 手牌容量 | 5（上限 8） | 4–8 | 选项过载，玩家不思考只乱塞 | 凑不出字，卡在资源上而非构想上 |
| **成功补牌数** | 2 | 1–3 | 大于 2 = 手牌净增长，失败无代价 | 小于 2 = 成功也在枯竭，游戏变成资源管理 |
| 失败补牌数 | 0 | 0–1 | 调到 1 则失败只占格，C3 的 D1 决策失效 | （不可低于 0） |
| `λ` | 由标定得出 | 0–20 | 手牌过度"喂答案"，探索感消失 | 失败率失控，等同纯随机 |
| `BASE_WEIGHT` | 1 | 0.5–2 | 可达性权重被稀释，加权失效 | 稀疏部件几乎不出现 |
| 同部件上限 | 2 | 1–3 | 容忍"五张禾"，无聊手牌 | 过严，凑字自由度下降 |
| `f*` | 0.20 | 0.15–0.25 | 挫败 | 无悬念 |

**旋钮联动**：`成功补牌数` 与 `f*` 是一对——提高 `f*` 必须保证成功补牌数 ≥ 2，否则玩家会陷入"失败更穷、成功也穷"的双重枯竭。

## 视觉/音频需求

- 手牌卡片吸取时的手感要**像从纸堆里抽一张**，不是 UI 弹入。
- 补牌时应有"翻出"的动势；洗牌时有纸张声。
- 死手防护触发的替换**不可以动画暴露**（不能显示"系统帮你换了一张"），否则玩家会发现有兜底而不去记字。
- 细则归 P2 / P6。

## UI需求

- 手牌上**只对农书已收录的组合**高亮"可以写成X"（与 C3 R6 的预览规则一致，不能提前泄露未知组合）。
- 手牌不足 2 张时，结束回合按钮变为显著可用。
- 补牌动画期间禁止拖拽（避免拖到正在飞入的牌）。

## 验收标准

- [ ] **A1** 回合开始补至 `Capacity`；成功补 2；失败不补；回合结束不改手牌
- [ ] **A2** 成功补牌受 `Capacity` 封顶，不产生"欠账"（无隐藏队列）
- [ ] **A3** 同一部件在手牌内不超过 2 张（跑 1000 次发牌，0 违规）
- [ ] **A4** 随机 1000 次补牌，**0 次**出现死手（死手防护生效）
- [ ] **A5** 实测失败率在 `f* ± 0.05`；λ 标定后误差 ≤ 0.02
- [ ] **A6** 洗牌消耗 RNG 且写回 `FarmState`：同种子两次运行牌堆序列完全一致
- [ ] **A7** 连续失败 3 次后手牌见底但**不卡死**：可提前结束回合，下回合补满（E1）
- [ ] **A8** `hand_growth` 只影响下一回合，不累计、不溢出（E5/E6）
- [ ] **A9** 与 C3 联合测试：单次失败后仍存在 ≥ 1 个可成字组合
- [ ] **A10** 静态检查：C2 内无静态随机源、无 `UnityEngine.Random`、无时间戳参与
