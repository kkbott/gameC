> **状态**: 设计中 · v0.1
> **作者**: 创意总监 + agent
> **最后更新**: 2026-11-17
> **实现支柱**: P4 一季不回头（祟气只涨不主动降，逼玩家接受压力）、P3 水乡会说话（祟有性格）
> **系统层级**: 核心层 / MVP / 设计顺序第 9
> **上游**: [C1 田块](plots-and-slots.md) v0.1、[C4 字效](character-effects.md) v0.1、[F3 状态层](farm-state.md) v0.1

## 概述

祟气是**"这片地现在有多不安"的一个数字**。它每回合涨，涨到满就招来祟夜。

它存在的意义不是"做一条血条"，而是**把玩家的布局质量变成可预见的后果**：田空着不写字 → 祟气涨得快；写错了留下祟字 → 涨得更快；整片田写满写对 → 几乎不涨。玩家第一次看懂这条曲线时，会意识到"我写的每一个字都在替我压住这片地"。

**它是玩家唯一能主动管理的威胁计量**，所以必须全程可见。

---

## 玩家幻想

> **「地空着，它就会醒。」**

- 玩家不该觉得祟气是"系统随机施压"，而是**自己放任的后果**。
- 满格前的最后一回合应该有明确的紧张感：还差一格，今晚要不要硬撑？
- 祟气降下来的时候要有**松一口气**的反馈——不是数值变小，是风声变安静。

## 详细设计

### 核心规则

**R1 · 字段**

```
QiOfSui : int, 范围 [0, Qmax]，Qmax 初值 12
存在 FarmState 中（F3），随存档走
```

**R2 · 每回合结算时增量（挂在 F2 R5 第 3 步）**

```
ΔQ = NATURAL_DRIFT
   + OPEN_PLOT_PENALTY  × 空田数
   + SUI_CHAR_PENALTY   × 场上祟字数
   − FALLOW_RELIEF      × 休耕田数

NATURAL_DRIFT     = 1      // 时间本身就在积祟，不能靠"什么都不做"苟
OPEN_PLOT_PENALTY = 2
SUI_CHAR_PENALTY  = 3
FALLOW_RELIEF     = 1

QiOfSui = clamp(QiOfSui + ΔQ, 0, Qmax)
```

> **口径说明（对齐 F1 §4.4）**：F1 定义了 `suiCharCount`（祟字占用的田块数）。本公式里的"场上祟字数"就是 `suiCharCount`，F1 只提供口径，数值归本系统。

**R3 · 触发祟夜**

```
回合结算结束时若 QiOfSui >= Qmax：
  标记 pendingNight = true
  祟夜在本回合结算内的第 5 步立即结算（F2 R5 固定顺序）
  祟夜结束后 QiOfSui = 0
```

**R4 · 祟气只降不清零（除祟夜）**

- 祟夜结算后归零（R3）。
- 其余任何时候**只增不减**，唯一的减项是"休耕"（`FALLOW_RELIEF`）。
- **不提供"花钱降祟气"**——不做。祟气的解只有两个：把地写满、或者承受祟夜。

> 为什么不做"花钱降祟气"：那会让祟气变成一条可购买的难度滑块，压力立刻消失。第一款游戏里，**威胁必须有不可消除的部分**。

**R5 · 空田数是主驱动**

`OPEN_PLOT_PENALTY = 2` 是四项里最大权重，这是刻意设计：

| 玩家行为 | ΔQ | 一季（7 回合）累计 | 后果 |
| --- | --- | --- | --- |
| 6 田全写满 | 1 + 0 = 1 | +7 | 一季一次祟夜 |
| 5 写 1 空 | 1 + 2 = 3 | +21 | 一季两次祟夜 |
| 3 写 3 空 | 1 + 6 = 7 | +49 | 每回合都危险 |
| 1 个祟字未清 | +3 | — | 相当于多空了一块半田 |

**R6 · 可见性**

祟气必须**始终可见**，且以"土地本身的状态"呈现（雾气、虫鸣、天光变暗），不能只靠一条数字条。

- 达到 `Qmax × 0.75` 时进入**预警态**：颜色、音效、字灵态度全部变化。
- 预警态的祟气变化必须在**回合开始时不预告、回合结算后立即反馈**，让玩家明确知道"是这一步让它满了"。

**R7 · 与 TUI 的边界**

C6 只算数。**祟怎么进、怎么打，是 C7 的事。** C6 的输出只有两个：`QiOfSui` 的值，和 `pendingNight` 标志。

### 状态和转换

```
Calm (Q < 0.5×Qmax)       --[ΔQ 累积]--> Uneasy (0.5–0.75)
Uneasy                    --[ΔQ 累积]--> Warning (0.75–Qmax)   // 预警态
Warning                   --[Q >= Qmax]--> Triggered
Triggered --[C7 祟夜结算完成]--> Calm  (Q = 0)
```

### 与其他系统的交互

| 系统 | 方向 | 接口 | 所有权 |
| --- | --- | --- | --- |
| C1 田块 | 上游 | 读 `PlotStatus` 统计空田数、休耕田数 | C1 拥有状态 |
| C4 字效 | 上游 | `fallow_restore` 使田进入休耕语义（用于 `FALLOW_RELIEF`） | C4 触发，C6 读取 |
| F3 状态层 | 上游 | `QiOfSui` 字段 | F3 拥有存储 |
| F2 步进 | 上游 | 挂在结算顺序**第 3 步** | C6 拥有计算 |
| C7 祟夜 | 下游 | 输出 `pendingNight` 与 Q 值；接收"已结算"通知后归零 | C7 消费 |
| P2 / P5 / P6 | 下游 | 读 Q 值做氛围与预警 | — |

## 公式

### 4.1 增量

```
ΔQ = 1 + 2×openPlots + 3×suiChars − 1×fallowPlots
Q  = clamp(Q + ΔQ, 0, 12)
```

### 4.2 一季的祟夜次数估算

```
目标：每季 1–2 次祟夜（概念 §3.3）
一季 7 回合 → 需要 Q 累积 12–24
→ 平均每回合 ΔQ = 1.7–3.4
→ 对应"6 田里 0–1 块空"的健康布局
```

**平衡意图**：健康布局（写满、无祟字）一季一祟夜；偷懒布局（空两三块）一季两三次。玩家一旦摸清这条线，祟气就从"随机惩罚"变成"可管理的资源"。

### 4.3 预警阈值

```
warningAt = ceil(Qmax × 0.75) = 9
```

## 边缘情况

| # | 情况 | 处理 |
| --- | --- | --- |
| E1 | 全场 12 块都空 | ΔQ = 1 + 24 = 25 → 立即触发祟夜。**不能靠"什么都不做"苟过**，这是刻意的 |
| E2 | ΔQ 为负（大量休耕） | 允许，Q 下降至下限 0。但休耕没产出，是真实的取舍 |
| E3 | 同一回合既触发祟夜又到季末 | 顺序固定：祟夜（第 5 步）先于季末（第 7 步） |
| E4 | 祟夜中途读档 | 祟夜是**单个原子 Step**，不存中间态。读档只会回到祟夜开始前 |
| E5 | Qmax 被调参后旧档 Q 超上限 | 加载时钳到新 Qmax，记警告 |
| E6 | 玩家把田全写成祟字（故意） | 允许，但 ΔQ 会爆炸（每祟字 +3）→ 自我惩罚，不需要额外规则 |
| E7 | 休耕田同时被计为"空田" | **互斥**：`fallowPlots` 与 `openPlots` 不重叠。休耕田状态仍是 `Char`，只是不产出 |

## 调整旋钮

| 旋钮 | 初值 | 安全范围 | 太高会怎样 | 太低会怎样 |
| --- | --- | --- | --- | --- |
| `Qmax` | 12 | 8–20 | 祟夜太稀，威胁感消失 | 每回合都在守夜，变成纯塔防 |
| `NATURAL_DRIFT` | 1 | 0–2 | 时间压力过强，玩家无法从容布局 | 可以无限拖，节奏拖沓 |
| `OPEN_PLOT_PENALTY` | 2 | 1–3 | 空一格就崩，玩家被迫乱填 | 空田无所谓，"写满"策略失去意义 |
| `SUI_CHAR_PENALTY` | 3 | 2–5 | 一次失败=灾难，玩家不敢试 | 祟字无痛，失败惩罚只剩占格 |
| `FALLOW_RELIEF` | 1 | 0–2 | 休耕成免费降压，可持续性玩法失去代价 | 休耕无收益，玩家永不考虑 |
| 预警阈值比例 | 0.75 | 0.6–0.85 | 预警太早，紧张感钝化 | 预警太晚，玩家来不及反应 |

## 视觉/音频需求

- 祟气**不能只做成数字条**。主载体是环境：雾的浓度、水面的反光、虫鸣的密度、天光的冷暖。
- 预警态：字灵开始不安（对话变短、语气变差），风起。
- 祟夜触发瞬间：需要一次明确的"天色变了"的转场，这是全季情绪最高点。
- 细则归 P5 / P6。

## UI需求

- 祟气条**必须常驻可见**，放在不会遮挡田块的位置。
- 预警态要有"还差几步"的明确表达（例如刻度上的倒数），而不是只有一个百分比。
- 回合结算后，若有 ΔQ 变化，必须有归因提示（"空田 3 块 +6"），让玩家学会这条曲线。

## 验收标准

- [ ] **A1** ΔQ 四项计算与符号正确；休耕与空田互斥（E7）
- [ ] **A2** `Q = clamp(Q + ΔQ, 0, Qmax)`，两端都不溢出
- [ ] **A3** `Q >= Qmax` 时置 `pendingNight = true`，且 C7 结算后 `Q == 0`
- [ ] **A4** 全空田情况立即触发祟夜（E1 用例）
- [ ] **A5** 祟气无任何"花钱降低"的路径（静态检查：C6 内不出现 `Money`）
- [ ] **A6** 结算顺序：祟气计算（第 3 步）先于祟夜（第 5 步）先于季末（第 7 步）
- [ ] **A7** 健康布局（6 田写满）在 7 回合内只触发 1 次祟夜（数值回归测试）
- [ ] **A8** 读档后 Q 值与 `pendingNight` 一致（E4：祟夜为原子 Step）
